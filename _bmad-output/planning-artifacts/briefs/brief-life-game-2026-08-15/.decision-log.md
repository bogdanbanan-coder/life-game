## 2026-08-15 — Sandbox experience boundary

- **Decision:** The application is a pure Life sandbox with no authored challenges, progression, achievements, prescribed goals, or designed “satisfying moment.”

## 2026-08-15 — Player action boundary

- **Decision:** Keep the core player actions to making cells alive, running or pausing the simulation, highlighting an area, saving it, choosing a saved figure from the bank, and pasting it onto a board.
- **Reason:** The user said “nothing more or less” after restating these interactions.
- **Status:** Confirmed as the design boundary; correction behavior and exact bank semantics still need clarification.

## 2026-08-15 — Simulation timing terminology

- **Decision:** Describe Life state transitions in generations rather than rendering frames.
- **Reason:** Conway's rules conceptually update the whole board per generation; tying state changes to display frames would make simulation rate hardware- and rendering-dependent.
- **Consequence:** Architecture should separate simulation updates from rendering, even if the first implementation advances once per displayed frame.

## 2026-08-15 — Tool pool and correction behavior

- **Decision:** Provide Live, Die, Pause/Resume, Highlight, and Bank in the tool pool; one is always selected and Live is the default. Live drawing makes affected cells alive, while Die drawing makes them dead.
- **Reason:** Explicit user interaction specification.
- **Consequence:** Die is the direct correction mechanism for misplaced live cells.

## 2026-08-15 — Highlight and save flow

- **Decision:** Highlight operates by pressing on one cell, dragging to another, and releasing to select the enclosed area. Completion automatically pauses the simulation and opens a small naming window with Save and Cancel. Save adds the named figure to Bank; Cancel or clicking elsewhere discards it. The simulation resumes after either outcome.
- **Reason:** Explicit user interaction specification.
- **Consequence:** Figure capture is a modal, auto-paused operation with click-away cancellation.

## 2026-08-15 — Bank and placement flow

- **Decision:** Opening Bank pauses the simulation and shows all saved figures with their names. Choosing one closes the menu and places a transparent preview on the field; the player moves it to the desired location and presses Resume to commit the placement and restart simulation.
- **Reason:** Explicit user interaction specification.
- **Consequence:** Resume doubles as the paste-commit action while a bank figure is staged.

## 2026-08-15 — Paste overwrite interpretation

- **Decision:** Treat “covers and grinds all the cells” as full rectangular replacement, including dead cells stored inside the saved selection. Cells outside the placed rectangle remain unchanged.
- **Reason:** The user explicitly confirmed that Bank paste replaces all cells on which the figure is placed—no more and no less.
- **Status:** Confirmed.

## 2026-08-15 — Post-command tool state

- **Decision:** After Pause/Resume or Bank completes, Live becomes the selected tool. The next press or drag over field cells applies Live behavior; input that does not touch a field cell has no effect on cell state.
- **Reason:** Explicit user clarification in response to the persistent-mode versus immediate-command question.
- **Consequence:** Pause/Resume and Bank behave as transient commands that recover to the default Live drawing mode.

## 2026-08-15 — Board boundary rule

- **Decision:** Use a finite board. Positions beyond its boundary are permanently dead and cannot become alive.
- **Reason:** Explicit user direction.
- **Consequence:** No wrapping or infinite expansion occurs; edge contact can alter, clip, or destroy patterns. Simulation logic must treat out-of-bounds neighbors as dead.

## 2026-08-15 — Fixed field and movable view

- **Decision:** Keep field dimensions fixed for the duration of a game session while allowing the player to zoom the view and move the camera across the field.
- **Reason:** Explicit user direction.
- **Consequence:** Model board coordinates independently from viewport position and zoom. Navigation changes presentation only, never field size or cell state.

## 2026-08-15 — Window resizing priority

- **Decision:** Treat window resizing support as optional; it may be omitted if difficult.
- **Reason:** Explicit user scope preference.
- **Consequence:** A fixed-size application window is acceptable for the study-project MVP.

## 2026-08-15 — Initial field dimensions

- **Decision:** Start new sessions with a small square field by default. Allow optional configuration of width and height independently, including rectangular fields.
- **Reason:** Explicit user direction.
- **Consequence:** The exact default cell count is deferred to implementation, but the data model and setup path must not assume width always equals height.

## 2026-08-15 — Session and bank persistence

- **Decision:** Support multiple game sessions. Automatically save a session's condition when the player leaves it. Maintain one persistent figure bank shared across every session.
- **Reason:** Explicit user direction.
- **Consequence:** Session persistence and bank persistence are separate scopes. A figure captured in one session must be available for placement in another.
- **Open detail:** The precise contents of saved session condition remain undefined; the session-management interface is specified below.

## 2026-08-15 — Session browser

- **Decision:** On launch, show a horizontally scrollable list of all sessions. Each session displays its name, a preview image of what the player last saw in that session, and an adjacent Delete button.
- **Reason:** Explicit user interaction specification.
- **Consequence:** Leaving a session must capture a last-view preview in addition to persistent session data.

## 2026-08-15 — Session creation and deletion

- **Decision:** Provide a Create button that opens a small session-name dialog. Each session's Delete button opens a confirmation dialog before deletion.
- **Reason:** Explicit user interaction specification.
- **Consequence:** Accidental deletion is guarded. Because the figure bank is global rather than session-owned, session deletion does not delete bank figures under the current model.

## 2026-08-15 — Session restoration

- **Decision:** Treat camera position and zoom as part of persistent session state. When a session opens, restore its cells and last view, then begin advancing generations immediately.
- **Reason:** Explicit user clarification.
- **Consequence:** Sessions always reopen running rather than preserving a paused state. The stored preview depicts the initial restored view, which may begin changing immediately after load.

## 2026-08-18 — Implementation stack

- **Decision:** Use C++23 with CMake, raylib 6.0, and raygui 5.0. Pin the raylib and raygui dependency versions.
- **Reason:** The user chose raylib plus raygui and prefers C++23 when stable. C++23 is a published standard; raylib and raygui support C/C++ and the required macOS/Linux platforms.
- **Constraint:** Compiler and standard-library implementation coverage for C++23 is not perfectly uniform. Use only features that compile and behave correctly on both the selected macOS and Linux toolchains.
- **Consequence:** Keep simulation and persistence in framework-independent C++; isolate raylib/raygui behind the application and presentation layer so the later source-replication experiment does not absorb UI-library concerns.

## 2026-08-18 — Visual and audio direction

- **Decision:** Use a restrained mathematical-tool aesthetic: dark field, bright live cells, subdued dead cells, zoom-aware faint grid lines, a clear highlight color, translucent staged figures, and simple flat controls. Include no audio.
- **Reason:** The user accepted the proposed direction without changes.
- **Consequence:** Prioritize legibility and state clarity over decorative art, animation, narrative presentation, music, or sound effects.
